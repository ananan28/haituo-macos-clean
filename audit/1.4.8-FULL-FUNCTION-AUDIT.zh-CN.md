## 一、实际应用运行发现（优先处理）
### R1 Windows 设置重启丢失——重复实测
真实 1.4.8 已构建应用，全新独立配置目录。设置品牌标记 AUDIT-RESTART-MARKER，保存等待后立即读回成功；完全退出并以同一目录重启，标记变为 undefined。两轮重复出现；默认禁止中文仍为 true。
证据：39882075279/120181526417 与 39882441890/120182734129，PERSIST-MARKER-SAVE 通过、RESTART-PERSISTENCE 失败。
定位：src/app/bundles/main.js:24931 haituoProtectedRead、25216 $p、25256 tm、29898 顶层 tm() 调用。
代码链：tm 在顶层读取设置；protectedRead 解密异常返回空对象；$p 把它视为待迁移的正常配置并调用 em 写入默认值。独立测试确认读取失败路径触发四次写入。启动早期解密与覆盖的完整因果需要修复者再加诊断确认，不应只加延时掩盖。
要求：读取失败与文件不存在分离；禁止默认值覆盖不可读原件；备份、可恢复错误提示；加密初始化就绪后读取。恢复旧配置验证后再写迁移结果。

### R2 macOS 全新环境启动停留加载页——CI 实测，真实电脑待复核
通过 LaunchServices 正常打开 ARM64 应用，不使用内部 runtime hook，窗口可见但未进入 Signal 安装/收件箱，设置窗口仍可正常操作。多轮出现，早期等待 80 秒亦未完成。没有足够证据断定是所有实体 Mac 的通用故障，也不能认定已通过首次启动。
证据：39879739414、39879992994、最新 Mac job120182733805。
要求：记录初始化各阶段、数据库/网络/权限等待及超时；用断网/代理/正常网络和实体 ARM Mac 新用户目录复测，明确卡点，禁止永远转圈。

### R3 Windows 子账号样式同步不一致——重复实测
设置运行用例两次出现 Saved child setting mismatch: chatTextColor；Mac 对应用例通过。
证据：39880038052，jobs120174931239、120175552974。
定位方向：main 配置读写/广播、preload 接收配置、子进程启动读取。可能与 R1 共因，但尚未证明，不可合并后直接关闭。
要求：主窗口改颜色，已开与新开子账号、切换、重启均一致。

## 三、此前异常路径仍须一起验收
1. Windows 数据库恢复密钥处理：safeStorage 不可用或失败路径可能删除原恢复密钥。异常用例失败（39876741697）。保留原密钥与原密文，不能失败后当成全新安装。
2. macOS 数据库密钥封装：已有有效恢复密钥时，encryptString 抛错或回读 decryptString 抛错缺乏安全回退；两项异常测试失败（39879879400/120174418351）。已有加密密钥解密失败保留恢复密钥的用例通过。
3. Mac 本地 API 设置文件实测未加密；数据库本身是否加密、恢复密钥是否明文、API 是否加密是三件事，不能混为“全数据加密”。
4. 正式构建链可携带 runtime-test-hook（build --test / prepare-windows）。环境变量保护不是远程漏洞证据，但测试钩子应与正式发行严格分离。
5. Windows 跟随窗口高频循环与 owner 关系仍非真正嵌入；需拖动/最大化/多屏/焦点物理验证，现有 fixture 通过不代表完全无分离感。
6. 截图多屏匹配、休眠恢复、系统屏幕权限，不能靠 CI 单屏虚拟显示器结案。
7. Signal 悬停预览等待多个 pending 与缓存只按文本的策略仍需慢网和同文不同上下文测试。
8. Windows 无发行签名，Mac ad-hoc 非公证；这是分发信任问题，不能仅以 hash 清单替代发行者身份验证。
9. 构建依赖锁定及可复现性不足；不能把一次构建成功视为供应链已验证。
以上非本轮全部重新复现，按对应历史证据与当前源码复核，修复后补独立回归。
